# 架构决策

## 状态

V1 核心功能基线，2026-10-25。

## 决策

### 运行时

使用 .NET 10 LTS 与 WPF。.NET 10 在本机已验证可构建 WPF，官方支持到 2028-11-14。当前机器没有系统级 .NET SDK，因此 SDK 安装在工作区 `D:\codex\.dotnet`，避免影响已安装的 .NET 7/8 运行时。

### 项目划分

- `LiangTu.App`：WPF 唯一启动项目，也是组合根。按 Data、Infrastructure、Services、ViewModels 和 Windows 分离 SQLite、系统适配、应用服务与窗口。
- `LiangTu.Core`：纯 .NET 逻辑。负责不依赖窗口对象的规则，例如导入去重决策、晾衣绳自动隐藏状态机、排序和编辑保存协议。不得引用 WPF、Win32 或 UI 类型。
- `LiangTu.Core.Tests`：MSTest 状态机与领域规则测试。
- `LiangTu.App.Tests`：数据库迁移、导入、排序和原位编辑集成测试。

不在阶段 0 预先拆分更多项目。只有当独立基础设施程序集能明显降低测试成本或依赖泄漏时才新增项目，避免形式化分层。

### 依赖策略

- 优先使用 .NET 和 Windows 自带能力。
- 新依赖必须有明确用途、兼容当前 LTS、许可证可接受、仍在维护，并评估安装包体积与运行时分发成本。
- NuGet 包版本集中在 `Directory.Packages.props` 管理。
- SQLite 使用 Microsoft 维护的 `Microsoft.Data.Sqlite`，版本集中管理，数据库通过 `user_version` 执行渐进迁移。
- 视觉令牌集中在 `Themes/LiangTuTheme.xaml`；窗口只定义自身布局，不复制全局色彩、圆角和阴影。
- 晾衣绳由透明内容窗口与独立顶边热区窗口组成；内容窗口通过真实 `Top` 坐标动画完成垂落，图片圆角由 `RoundedImage` 自绘裁切。
- 应用使用命名事件实现单实例唤醒；发布采用 win-x64 self-contained 单文件配置，关闭裁剪以保护 WPF/XAML 反射行为。

### 核心边界

以下规则不依赖具体 UI：

- 所有图片只经过统一导入服务；校验、去重、落盘成功后才进入可展示状态。
- 图片资源、晾衣绳条目、贴图实例、缩略图缓存是不同概念。
- 隐藏窗口、关闭贴图或退出 UI 不能删除原图和持久数据。
- 编辑保存采用临时文件、验证、原子替换的协议，并配合启动恢复。
- 两分钟自动隐藏是状态机：唤出、交互暂停、恢复计时、手动隐藏分别建模。
- 鼠标检测优先使用窗口鼠标事件、热区与系统消息；禁止高频轮询。
- 应用自身写入剪贴板时必须打标记，避免自动收集循环。
